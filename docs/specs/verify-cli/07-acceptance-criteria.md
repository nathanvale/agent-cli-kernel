# `verify-cli` specification, part 7 of 11: acceptance criteria

This part belongs to Testing Decisions. Each criterion gives an observable
result and the test that shows it. A test is named by its title, as the build
has it. "Example CLI" is the author skill's example, `moons`, in a repository
laid out as TD1 says.

The last column says what has run. `Linux` is the claim tag "passed on Linux":
the build's end-to-end run in a container, and on macOS too. `macOS` is
"passed on macOS only": the build's tests, which this revision ran again at
`f7f4d69`, 218 of 218. `not run` is "designed and not run". The evidence
behind each is in [part 10](10-traceability.md#acceptance-criteria).

A criterion that names an exit 70 line passes when `stderr` holds a line
starting `verify-cli: RAW FAIL <id>:` for that id. Other such lines may also
be there.
